# stagingのアクセス制限と公開設定

確認日: 2026-09-28（JST）。当日の実クラウド確認と本人のログイン成功を基にしたメモです。リポジトリ整理ではクラウドを変更していません。実ID・AUD・メール・ホスト名・個別管理URLは記録しません。

## 設定と理由

| 項目 | 設定 | 影響・理由 |
| --- | --- | --- |
| 保護対象 | 専用staging Worker全体 | 全URL・API・静的ファイルでログイン必須 |
| bypass | なし | トップ、ヘルプ、healthも保護 |
| 許可条件 | 本人1名のメール完全一致、Allow | ドメイン全体やアカウントメンバー全員を許可しない |
| セッション期間 | 1時間 | 発行したセッションの期限。無操作時間ではない |
| 認証方法 | ワンタイムPIN（OTP） | 本人のログイン操作はメール送信を伴う |
| IdPの固定 | なし（有効IdPを利用） | IdPを追加したら影響を再確認 |
| アプリの認証 | Access JWTの署名・issuer・audienceを検証 | 外側のAccess保護だけに依存しない |
| 公開入口 | Custom Domainのみ | workers.dev・preview無効、通常routeなし |
| データ | 専用staging D1 | ローカル・productionから分離 |
| AI・拡張・demo | 全OFF | 配備と認証境界の検証に限定 |
| 費用 | Workers Paid基本料金を除き月$5を目安 | 課金の硬い上限ではない |

## 管理場所と変更時の注意

- Cloudflare Dashboard → Workers & Pages → 対象Worker → Accessで保護範囲を確認します。
- Zero Trust → Access → Applicationsで対象アプリ、セッション期間、ポリシーを確認します。実メールは本人が管理画面で照合します。
- 本人限定ポリシーは再利用可能です。確認時点で利用アプリはstagingの1件。今後共有した場合、条件編集は関連アプリすべてへ影響します。
- ログイン画面の組織表示名は組織内のAccessアプリ共通です。表示名の変更目的で認証用team domainを変更しないでください。
- 実配備設定は手元のGit管理外ファイルに分離しました。選択方法は[公開情報と履歴管理](リポジトリ-公開情報と履歴管理.md)を参照してください。
- Accessアプリ再作成時はAUDが変わります。手元の設定を更新し、再build・dry-run・配備後に未認証遮断と本人ログインを確認します。生成済み設定へ`--env`を重ねません。
- 新しい公開入口は、専用WorkerのAccess保護を確認してから追加します。[運用手順](operations.md)に従ってください。

## 検証済み・未検証

2026-09-28にページ・API・CSSの未認証アクセスがAccessへ転送され、偽の認証ヘッダーでも通過しないこと、workers.devが無効なことを確認しました。本人のOTP受信とアプリ表示も成功し、認証後UIとD1の認証後APIによる書込みを確認しています。

実AI、会話の実環境での保存・復元・削除、アプリ自身のメール送信、決済は未検証です。全モデルOFFではUIから会話を保存できません。ローカル成功を実クラウドの未検証部分の代わりにしません。

WranglerのOAuth認可は当日の作業後に取り消しました。次回配備では再認可が必要です。過去の認可コードや旧プロジェクトの上流キーの未確認事項は[作業ログ](staging-work-log.md)と[廃止記録](旧プロジェクト-廃止記録.md)を参照してください。履歴整理を鍵の失効確認の代わりにはしません。

## OTPが届かない場合

1. 許可ポリシーの本人メールと入力文字列・受信先を本人が照合します。
2. 迷惑メール・隔離・受信拒否設定を確認します。OTP、メール本文、Cookieを会話やリポジトリへ貼りません。
3. 再送を連打せず最新コードを一度だけ送信します。使用済みと出た場合は、同じブラウザでアプリを開き、既にログインできていないか確認します。
4. 解決しなければ[Cloudflareのメール未着手順](https://developers.cloudflare.com/support/troubleshooting/general-troubleshooting/not-receiving-cloudflare-emails/)を確認します。配送状態を確認せず送信抑止と断定しません。

送信済み表示だけでは配送成功を証明できません。[公式OTP手順](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/one-time-pin/)を参照してください。
