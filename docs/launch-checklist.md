## 設計 / キックオフ

- [x] 認可モデル（IDOR防止・オブジェクトレベル認可）を設計した ─ 会話・要求台帳・資料・ジョブ・契約の取得/更新/削除を所有者IDで照合。他所有者は404。`tests/`の所有権テストと`/api/chat/requests/:id`の他所有者404で確認
- [x] パスワード保管方式を決めた ─ Better Authの既定ハッシュ（ソルト付きKDF）を上書きせず使用。社内・個人向けはAccessでアプリにパスワードを持たない
- [x] シークレット境界を定義した ─ Secretは`wrangler secret`とGit管理外のローカルファイル。クライアント公開のbuild変数（`VITE_`）は未使用。[Secrets補足](../rules/secrets.md)
- [x] データモデル方針を決めた ─ D1（SQLite、UTF-8）。時刻はUTCのepochミリ秒で保存。migrationは連番SQLで適用済みを編集しない
- [~] 決済アーキを設計した ─ Polar sandboxで署名付きwebhook・raw body検証・再送/重複/順序逆転・契約権限の突合を実装済み（[決済](billing.md)）。アカウント削除APIが無く、退会時のサブスク自動キャンセルと会計整合は未設計。決済を有効にする複製先で設計する
- [x] レート制限の方針を決めた ─ 認証はBetter Authのdatabase保存で60回/60秒、認証後APIは利用者ごと120回/分、チャットは10回/分・60要求/日・同時1件をD1の原子的予約で判定
- [ ] 法務要件（プライバシーポリシー / 特商法 / GDPR対象判定）を洗い出した（複製先: 用途と利用者範囲で決まる。公開向けは必須）
- [ ] サービス名が他言語で不適切でないか確認した（複製先）

## Cloudflare実配備の受入（個人・社内向け）

最初の複製先（本人1名・Access保護の通常staging、2026-10-06〜08）が実際に確認した項目を、用途に依存しない形にまとめた。各配備で複製先の記録へ写し、結果を埋める。注意点の背景は[運用手順](operations.md#複製先の実配備で確認した注意点)。

### 配備前

- [ ] 専用のD1・R2（公開アクセス無効）・Access app/policyを新規作成した。旧検証環境や他用途のリソースを流用していない
- [ ] 複製直後に固定Node/pnpm、frozen install、全migration、`pnpm check`、preview smokeを複製先自身で通した
- [ ] 実値入りの設定はGit管理外に置き、本人が非表示入力で作成した。build後の生成設定と照合した（値を表示しない）
- [ ] 対象のアカウントとD1を、管理画面と保存済み設定で独立に照合した
- [ ] 実D1の適用状況を読み取り専用SELECTで照合した（`migrations list`は使わない）。想定外の履歴・部分schemaなら止める
- [ ] 複数文triggerを含むmigrationは送信用SQL（`scripts/d1-wire.ts`）で適用する。1本ずつ、失敗・不明時は再送しない
- [ ] 配備はbuild → 生成設定一致 → dry-runの順に通し、失敗したら配備しない。各段階に時間上限を設けた
- [ ] deployでは既存Worker名を明示し、`CLOUDFLARE_ENV`や`--env`を重ねていない
- [ ] 使うモデル・サービスの単価と制限を一次資料で確認し、回数・期間・費用目安・停止条件を本人が承認した。目安は硬い上限ではない
- [ ] 初回は全OFF・公開経路なしで配備する計画にした

### 配備直後

- [ ] 管理画面で、専用ドメイン以外の入口が無い（workers.dev・preview無効、通常routeなし）こと、想定したbindingだけがあることを確認した
- [ ] Workers一覧に意図しない別名Workerが無い。あれば本人許可後に削除した
- [ ] Cookieなしの要求がAccessログインへ転送される（トップと保護API）
- [ ] 本人認証済みブラウザで画面に到達し、OFF時はモデルなし・送信不可である
- [ ] ON版へ切り替えた後、選択モデル・有効な拡張・入口の数を値を出さずに確認した
- [ ] ブラウザが読み込んだbundleが直近のbuild成果物と一致し、追加したAPIが応答する
- [ ] 本人報告とエージェントが直接確認した事実を分けて記録した

### 受入

- [ ] 架空データで、選んだ機能の最小経路（例: 1回のAI回答、保存、再読込後の履歴復元）が成功した
- [ ] 同じ要求の再送で再生成されない（要求台帳の照合と履歴復元）
- [ ] 別利用者・未認証での取得/更新/削除が拒否される
- [ ] 実行回数は直接観測した値で記録し、上限超過は成功と分けて報告した
- [ ] 終了時に自動照会・定期処理が残っていない

### 停止・後始末

- [ ] 試験データ（会話・資料・保存物）を削除し、ストレージの物理不在を確認した。資料の削除だけでは会話内の引用断片は消えない
- [ ] 消費台帳・利用記録は削除・リセットしていない
- [ ] 停止はOFF版配備 → Access policyをBlock → 対象アプリの既存トークン取消、の順で行った
- [ ] 取消後にブラウザがAccessログインへ転送されることを確認した。自然期限を取消の証拠にしていない
- [ ] 取り消したのは対象アプリのセッションだけ。Accessのlogout URLや他用途のトークンで代用していない
