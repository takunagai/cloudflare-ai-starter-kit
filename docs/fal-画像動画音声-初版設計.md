# fal画像・動画・音声の初版設計

メディア（画像4・動画4・音声4の12 endpointと参照画像アップロード）の初版設計。指定モデルと共通基盤の考え方を示す。入力上限・保存条件・取得経路・migrationは[M-0差分設計](fal-メディア-M0差分設計.md)、実装は[M-1](M1-共通メディアジョブと保持.md)〜[M-5](M5-メディア統合と隔離複製検証.md)、公式根拠は[調査メモ](../references/fal-media-contract-20261002.md)にある。工程計画と工数見積りは[履歴](archive/fal-初版設計の工程計画と工数.md)へ移した。

## 位置付け

- 採用: 12 endpointと参照画像アップロードを初版で完成させる。Jevと同じ単一パッケージ/主Workerの構成を維持する。Directorは対象から除外する。
- 12件は共通ジョブ基盤で実装し、画像/動画/TTS/音楽の目的を選ぶと、対応モデルと設定を表示する。
- 参照画像7日、生成物30日、所有者ごと保存1 GiB。参照動画/音声アップロードと高度な音楽構成編集は初版から除外し、単一/2話者TTSと長さ指定の音楽までに絞る。
- RAGと別のprivate R2と、通常環境の主Workerの専用素材取得パス（そのパスだけ期限/用途限定token認証）。入力サイズ・生成量・同時処理上限と環境合計10 GiB、ジョブ本文終端30日・本文なし台帳90日は[M-0](fal-メディア-M0差分設計.md)が正本。
- 技術・実接続の未検証: fal側の保持/公開条件、Store-IOと非同期回収、12件への適用、token計数、実Access/fal到達性、実価格・利用権限・品質。

fal連携はJevと同じく任意利用・初期OFFで、APIキーやR2なしでも標準機能は動く。モデル採用を実接続ONや課金許可に読み替えない。

## 指定モデルと初版の操作

下表は初版の操作範囲。[公式確認と制約](../references/fal-multimodel-feasibility-20261002.md)に各endpointの根拠を保存する。

| endpoint ID | 用途・初版の操作 |
| --- | --- |
| `openai/gpt-image-2.5/sunburst/text-to-image` | テキストから画像。サイズ/縦横比、品質、枚数、背景、形式 |
| `openai/gpt-image-2.5/sunburst/edit` | 参照画像を複数アップロードして編集。任意のマスク画像もアップロード |
| `openai/gpt-image-2.5/flare/text-to-image` | テキストから画像。同じ設定UIを共有し、endpoint別に入力検証 |
| `openai/gpt-image-2.5/flare/edit` | 参照画像/マスクを使う編集。Sunburstとの明示選択 |
| `minimax/h3-max/text-to-video` | テキストから動画。秒数、解像度、対応する縦横比/seed設定 |
| `minimax/h3-max/image-to-video` | 開始画像・終了画像を選択して動画化。少なくとも一方を要求し、画像なしを暗黙のテキスト生成にしない |
| `minimax/h3-max/reference-to-video` | 複数参照画像の順序を保持し、必要時は開始/終了画像も指定。参照動画/音声入力は初版対象外 |
| `minimax/h3-max/camera-controls` | 開始画像とカメラのキーフレームを指定。簡単なプリセット＋時刻/方位/仰角/距離の編集表を推奨 |
| `google/gemini-3.8-flash-tts` | 読み上げ本文と演技指示を分離。既定音声の選択、単一話者/2話者の台本入力を推奨 |
| `google/gemini-3.8-flash-lite-tts` | 同じTTS操作からモデルを選択。endpoint別に契約テスト |
| `elevenlabs/tts/eleven-v4` | 読み上げ本文、音声、言語、安定性等、形式。初版は完成音声の取得・再生を推奨 |
| `elevenlabs/music/v2.5` | 音楽説明と長さ・インスト指定。初版はこの入力方式を採用し、細かなcomposition_plan編集UIは対象外 |

モデル対応と全パラメータ/全操作モードの対応は区別する。初版で扱わない入力はUIで出さず、サーバーでも拒否する。対応可能な品質・サイズ・形式を正方形1枚に固定せず選べるようにするが、providerの仕様範囲とアプリの受付上限の両方を検査する。生成結果の「画像を参照素材として動画へ使う」導線を含める。動画と別生成の音楽の自動合成・編集タイムライン・音声クローン・マイク収録は本計画へ自動追加しない。

## 共通基盤とアップロード

モデル登録表は目的、endpoint、入力schema、対応設定、出力schema、queue経路、許容media形式、制限を持つ。環境の許可リストとの積だけをクライアントへ返す。FAL_KEYはサーバー内に保持し、任意endpoint/任意JSONをそのまま中継するproxyは作らない。旧画像API/旧image_jobsの互換性を維持するか移行adapterで吸収し、必要な新SQLを追加する。Jevの0007を含む既存0001〜0007は変更しない。

新しい素材管理はRAGをONにせず使える境界にする。アプリが素材IDと所有者を管理し、生成要求では素材IDを受ける。別所有者・削除済み・未検証素材、非対応形式を拒否する。画像のMIME/実形式、ファイルサイズ、寸法、個数、合計容量、マスクと元画像の整合をサーバーで確認する。RAGと別のprivate R2・認証配信・削除の構成はM-0で設計採用済み。実リソースは未作成。

falへ入力を渡す時だけ、素材/用途/期限を限定した取得経路を発行する採用構成。非公開R2のURLをそのままfalが取得できるとは仮定しない。取得用URLはbearer相当としてログ/共有文書に出さず、アプリsessionやFAL_KEYを渡さない。queue待機時間とURL有効期限、再取得、ジョブ中の削除、失効後の取得拒否を設計・テストする。新しい通常環境の取得パスだけ短期token認証を必須とし、Accessの具体的なパス/直アクセス境界はM-2で検証、実変更とfal側取得は実接続の別承認で確認する。既存検証stagingと主アプリ全体の保護は変更しない。

出力は`images[]`/`video`/`audio`を共通の所有者付き素材へ正規化する。モデルID・設定・素材参照・requestIdと処理状態を履歴に残す。falの出力URLは非公開/恒久保存を保証しないため、private R2へ回収し、回収失敗時に再生成せず回収だけを再試行する案。取得先・redirect・実形式・容量を検証する。保存処理はストリームと容量上限を使い、動画/音声の全体をWorkerメモリへ展開しない。音声/動画再生では認証付きRange取得と期限/削除を検証する。アプリ側の削除をfal側コピーの削除完了とは扱わない。

画像・動画・音声ごとの利用枠と同時受付数を分ける。枚数/品質/画素、動画秒数/解像度、TTS入力量、音楽の長さに基づき受け付け、失敗や受付不明で自動再生成しない。音楽の長さはprovider任せの未指定にせず必須にする。単価未確認の見積額を硬い予算上限とは扱わない。実費条件は実接続で確認する。
