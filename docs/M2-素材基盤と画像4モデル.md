## 設定と管理場所

| 設定 | 動作・変更時の注意 |
| --- | --- |
| `ENABLE_MEDIA` / `MEDIA_ALLOWED_MODELS` | M-1の既定OFF/空配列を維持。ONかつ固定許可モデルのみ新規生成・アップロードを受け付ける。旧`ENABLE_IMAGES`とは独立 |
| `MEDIA_BUCKET` | RAGと別のprivate R2 binding。公開設定に実bucketを追加せず、未設定/OFFでも標準機能が起動する。保存済み素材がある環境でOFFにする際はbindingを保持する。実リソースの作成・変更は別承認 |
| `MEDIA_VERIFIED_IMAGE_MODELS` | 省略/`[]`で実画像生成を拒否。固定画像4 IDの重複なしJSON部分集合。各endpointのStore-IO/ACL/保持/回収・利用権限を工程Eで実確認するまで追加しない。単にFAL_KEYと許可一覧があることを確認済みの証拠にしない |
| `FAL_KEY` | server内だけで利用。未設定では生成・上流確認を拒否。素材のアップロード/本人閲覧/削除にfalのキーは不要。投入・閲覧は今回行わない |

管理場所は[素材API](../src/server/media/assets.ts)、[取得grant](../src/server/media/grants.ts)、[画像adapter](../src/server/media/image-driver.ts)、[設定型](../src/server/media/policy.ts)、[0009](../migrations/0009_media_assets.sql)。公開wrangler/5プリセットの実値・既定OFFと既存0001〜0008は変更していない。許可一覧と上流検証一覧を広げると送信対象・費用・データ取扱範囲が変わるため、ローカルfake成功だけで実モデルを有効にしない。

## 素材APIと保存

| 操作 | 契約 |
| --- | --- |
| `POST /api/media/assets` | `{bytes,contentType}`だけで1素材を予約。10 MiBまでのPNG/JPEG/WebP。serverが不透明IDとPUT先を発行。所有者同時2予約、10分で受付失効 |
| `PUT /api/media/assets/:id/file` | 本人・予約状態・期限・MIME/Content-Length/encoding・復旧gateを照合。宣言容量を超えるstreamを停止し、private仮objectを保存してからworkerdで実ファイル検査。上書き/再PUTは禁止 |
| `GET /api/media/assets` / `GET .../:id` | 本人metadataだけ。key、token、provider URLは返さない。期限・削除・参照利用可否を表示 |
| `GET/HEAD .../:id/file` | session→所有権→ready/期限→R2→状態再照合。private/no-store、nosniff、no-referrer。HEADは本文なし。画像Rangeは416。R2のETag/keyを未認証・別所有者へ返さない |
| `DELETE .../:id` | tombstone→新しい参照拒否/関連job取消意図/grant失効→R2 delete/head確認→容量CAS。失敗は削除待ちとし容量を保持。再試行/並行削除で二重解放しない |

ファイル名・client指定key・URL取込み・data URI・SVG・動画/音声アップロードは受け付けない。参照素材は検証完了＋7日、生成物は最初の保存＋30日。再読込・再利用・回収再開でID/版/起算点を変えない。生成画像も参照時の10 MiB・最大辺4096・最大8,294,400画素・要求合計50 MiBを満たす必要がある。自動縮小/再符号化は追加していない。

素材一覧・新規アップロード予約時に最大20件の期限/削除待ち回収を試す内部maintenanceを接続した。Cronや常駐監視は追加していない。アクセスは期限到達で即時拒否するが、停止中・アクセスなし・削除失敗時の物理削除をwall clockだけで保証しない。未完のwriter/書込み不明は10分経過だけでは容量を返さず、追加の証拠照合が必要。R2 putが遅れて終わる場合の削除/容量解放競合を避けるための保持であり、ジョブ受付不明の解放条件を緩めない。

## 実ファイル検査と資源

PNGは署名・全chunkのCRC/順序・IHDR・IDAT/IEND・末尾・アニメーションを検査し、deflateをstream展開して全画素行のfilter解除とpalette indexを検査する。8/16 bit、低bitのpalette/gray、Adam7も検査経路を持つ。展開量は寸法とbit深度から算出した行数/行幅に限定し、過剰展開・不足・不正filterを拒否する。alphaの有無もmetadataへ記録する。

JPEGはSOF/SOS/EOI/scan数/末尾を照合し、`@jsquash/jpeg` 1.6.0のMozJPEG WASMで画素をデコードする。警告付き補完結果は拒否し、警告本文は出力しない。EXIFによる自動回転は行わず、元bytes/符号化寸法を維持する。WebPはRIFF長/VP8・VP8L・VP8X/canvas/末尾とアニメーションを検査し、`@jsquash/webp` 1.5.0で実デコードする。MIMEと実形式、decoder寸法/画素byte数の一致を要求する。

画像だけは10/20 MiBの明示上限付きbufferを使う。isolate内では受信/読出し/デコードを1件に限定し、競合時429で本文を待機列へ溜めない。PNGの展開は行単位、WASMは呼出し単位のinstanceで実行する。最大画素数の3形式をローカルworkerdで検証した。全ての画像特性・圧縮率でのCPU/peak memoryや実Workersの負荷性能を保証したものではない。動画/音声の全体buffer化は追加していない。

マスクは先頭参照ID/版へ束縛し、同寸法のalpha付きPNGを要求する。先頭画像もPNGとし、順序変更/別画像への付け替え/自動リサイズを行わない。編集結果の厳密なmask一致・生成品質は工程Eで確認する。

## provider取得grantと上流境界

`/api/media-source/:grantId?token=...`だけをsessionの代わりにcapabilityで検証する。256 bit乱数のtokenを発行し、D1はSHA-256だけを保存。URLを本文・履歴・ログへ保存しない。owner/job/asset/版/role/ordinal/用途を束縛し、毎回リンク・状態・期限・取消・本文消去・復旧gateを照合する。文字列のprefixやCookieだけで取得を許可しない。

TTL30分、GET20回、転送予約は素材容量10倍、HEADは別枠20回を採用。GET/HEADはD1の条件付き更新で原子的に計上し、HEADは転送量に含めない。取消・素材削除・provider取得終了/終端・本文消去で取得拒否し、期限を自動延長しない。Range・余分/重複query・encoded/slash別名・他originを拒否。Bearer所持者がfal本人であることを証明する仕組みではない。実Accessのpath優先・別host・外部到達性・queryを保存する基盤ログの設定は工程Eの確認待ち。

4固定endpointの入力はprompt、明示寸法/編集auto、6品質、1〜4枚、PNG/JPEG/WebP、背景、対応形式だけの圧縮率、順序付き参照1〜8枚/任意maskへ変換する。任意JSON/endpointを中継しない。queue経路は固定ID＋保存済みprovider IDから構成し、返却されたstatus/result/cancel URLを使わない。No-Retry・fallback無効・開始期限120秒・Store-IO=0・非公開ACL/3600秒lifecycleを送る。これらの実適用/回収可能性は未検証。

結果は固定`rest.fal.ai`で300秒のCDN tokenへ交換し、許可した`v3b.fal.media/files/b/...`だけにBearerを付ける。redirect・別CDN・query/署名URL・公開保存へ切り替えない。tokenの返却期限も検査し、DB/clientへ保存しない。上流URL/件数/MIME/実byte数/形式/寸法と要求を検査してprivate R2へ保存する。回収は受付から1時間以内に限定するが、上流の実期限を長く仮定しない。

## 部分回収・削除・復旧

job/ordinalのobjectと検査receiptを独立記録する。部分保存の最大容量予約を保持し、保存済み分のID/bytes/期限を再作成しない。WASMやR2が失敗しても生成POSTを再送しない。`POST /api/media/jobs/:id/retry-collection`は同じprovider IDの完成済み結果だけを所有者が再回収する。取消/本文消去/1時間経過/書込み不明/復旧gateでは再開しない。M-1の3回自動回収・間隔・lease/CAS・新旧合算・利用量消費を維持する。

復旧witnessへuploadと出力objectの状態を追加し、grantを失効させる。復元前の正しい記録と一致しても、未完/書込み不明/削除未確認の素材があればgateを解除しない。台帳90日後の削除未確認容量も独立記録として保持する。本文30日/台帳90日、Jevの非保存/unknown保持、全コピー消去を保証しない条件は不変。
