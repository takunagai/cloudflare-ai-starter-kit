- Git公開検査57テスト成功、実効hooksPath・hookFiles・enginesの状態は全て有効。Git検査・作者情報・例外・baseline・登録は変更なし。

## 原因

現行コードの`compact`はコマンド全文から引用符を取り除き、環境操作の正規表現を適用する。このため、次の区別が失われていた。実際の拒否入力を再掲せず、合成データで再現した。

| 対象 | 判定の原因 | 調査結果 |
| --- | --- | --- |
| Pythonによるソース編集 | 子言語に渡す文字列中の変数名と閉じ括弧が、環境一覧コマンドと同じ正規表現に一致 | データと実行の区別に関する誤検出。任意Pythonを解析せず一律免除する修正は採用しない |
| ソース内の語句検索 | 引用した検索語にも環境操作判定を適用 | 誤検出。下記の限定した非実行形式だけを改善する |
| `env.ts`の閲覧 | `sensitive_name`が名前中の`env`と拡張子を検出 | 保守的なファイル名規則による拒否。中身は取得していないため、内容が安全と確認済みとは扱わない |

Git公開前検査は別のコードでソースモジュールを区別するが、それをPreToolUseの閲覧許可へ転用しない。秘密保護エンジン、フック登録、Git設定、例外、baselineはいずれも変更していない。

## 限定修正案

[レビュー用差分](proposals/secret-guard/literal-search.patch)は`protect_sensitive.py`への未適用patch。[判定ヘルパー](proposals/secret-guard/literal_search.py)を追加し、既存の広い環境操作判定より前に、次の形式だけを認識する。

```text
rg --no-config [-n] [-A 数値] [-B 数値] -- '文字列としての検索語' 明示したファイル1件
```

- 検索語は単一引用符。改行、展開、引用符の入れ子、バックスラッシュを含む形式はこの分岐では許可しない。
- `--`を必須とし、先頭がハイフンの検索語をオプションやパターンファイル指定として解釈させない。
- `--no-config`を必須とし、ripgrepの外部設定によるpreprocessorや追加対象の混入を防ぐ。
- shell wrapper、パイプ、リダイレクト、連結、glob、複数ファイル、directory、不存在ファイル、追加オプションは限定許可の対象外。
- 対象は既存の秘密パス判定とsymlink解決を通し、通常ファイルであることをmetadataで確認する。内容はフック内で読まない。
- 限定形式に一致しなければ従来の検査へ戻す。従来の検査で許可される全ての形式を新しく拒否する変更ではなく、任意shellの安全性を保証するものでもない。

影響はこの共通エンジンを使うCodex/Claudeの全プロジェクトへ及ぶ。ファイル名規則、Python heredoc、環境取得・表示、Git保護、秘密ファイルの例外化には変更を加えない。対象ファイルへのアクセス自体がユーザー指示で禁止されていれば、この形式でも読み取らない。

## 検証結果

[再現テスト](proposals/secret-guard/test_literal_search.py)は入力を文字列として判定するだけで、サンプルのshellコマンドを実行しない。空の架空ソースと、存在しない秘密ファイル名へ向けたsymlinkだけを一時ディレクトリに作成した。実秘密ファイル・認証情報・環境一覧・ネットワークは使用していない。

[候補生成と回帰検査](proposals/secret-guard/build_and_test.py)は現行コードを読み、限定差分を一時候補へ適用して検証する。設置先は書き換えない。再生成時は前提の挿入箇所が一致しなければ停止し、生成したpatchは毎回レビューする。

| 検査 | 結果 |
| --- | --- |
| 誤検出3種類の合成再現、新しい検索形式、秘密パス・symlink・展開・追加オプション等を含む比較 | 114判定成功 |
| 設置済みエンジンの既存回帰テスト | 12件成功、skipなし |
| 修正候補に対する同じ回帰テスト | 12件成功、skipなし |
| 設置済みエンジンの検証前後比較 | byte一致、未変更 |
| 修正候補の実フック発火 | 未検証、未適用のため |

追加テストには「限定許可へ入らず、従来と同じ判定になる」比較も含む。114件全てを危険操作の拒否テストと数えない。検出0・テスト成功を秘密漏えい不存在や完全なshell解析の保証にしない。

## 適用とアプリ作業の再開に必要な判断

推奨する次の範囲は、(1)この限定patchを共通エンジンへ適用し、回帰テストと実フックの架空ファイル検索を確認、(2)今回の秘密を扱わないアプリ編集を、対象ファイルと差分が明確な構造化patchで行う個別許可、の2点。**現時点ではどちらも実施しない。** 共通ルールの拒否迂回禁止を独断で緩和せず、再開方法を明示して確認する。

適用前に現行コードとレビュー済み差分を再照合し、不一致なら停止する。変更する設置済みコードは`protect_sensitive.py`だけ。回帰テスト・設定メモも追加更新するが、フックの登録、adapter、global Git identity、公開例外、既存Git保護は変えない。失敗時はこの差分だけを戻し、保護を有効に保つ。復旧のためにフック全体を無効化しない。

アプリでは`env.ts`を引き続き読まず、既に作成した専用設定型を使用する。拒否されたPython一括編集を再実行せず、provider・チャット・枠予約・API・公開テンプレート・テストの変更を個別の構造化差分として検査する。この再開許可に秘密閲覧、実設定閲覧、実AI、配備、Secret投入、実メール、mergeは含めない。
