# Vitest 5への更新（4.1.11 → 5.0.5）

確認日: 2026-10-19。2026-10-18の依存一括更新（[記録](dependency-update-20261018.md)）で見送ったVitestのメジャー更新。テストだけに影響し、配布するWorkerには含まれない。

## 1. 版・peer・engines

| 項目 | 内容 | 根拠 |
| --- | --- | --- |
| 採用版 | vitest 5.0.5（2026-10-15公開、dist-tag `latest`） | `npm view vitest time` / `dist-tags`。6.xは未公開（alpha・betaを含め0件） |
| engines | node `^22.12.0 \|\| ^24.0.0 \|\| >=26.0.0`。Node 26.10.0で満たす | `npm view vitest@5.0.5 engines` |
| peer | vite `^6.4.0 \|\| ^7.0.0 \|\| ^8.0.0`（8.3.4）、@types/node `^22.0.0 \|\| >=24.0.0`（26.6.5）。browser・coverage・jsdom系は未使用 | `npm view vitest@5.0.5 peerDependencies` |
| Cloudflare plugin | @cloudflare/vitest-plugin 1.4.4のpeerは`vitest ^4.1.0 \|\| ^5.0.0`。1.4.4が最新で、pluginの更新は不要 | `npm view @cloudflare/vitest-plugin` |
| ライセンス | MIT | `npm view vitest@5.0.5 license` |

`pnpm install`でlockfileを更新し、`pnpm install --frozen-lockfile`がpeer警告なしで成功した。lockfileからvitest 4系は消えた。

## 2. 移行ガイドとの照合

[Vitest 5の移行ガイド](https://vitest.dev/guide/migration)の破壊的変更を、`vitest.config.ts`と`tests/`の使用箇所と照合した。

| 変更点 | このリポジトリ | 対応 |
| --- | --- | --- |
| `clearMocks`の既定がtrue | `vi.fn`・`vi.spyOn`を使うが、テスト間で呼び出し履歴を持ち越す前提のテストはなかった | 不要（全件成功で確認） |
| `resolves`/`rejects`の自動awaitの廃止 | 未awaitの非同期アサーションは検出されず | 不要（全件成功で確認） |
| `vi.mock`のトップレベル必須、`test.sequential`等の廃止、`toThrow('')`の意味変更 | 使用0件 | 不要 |
| pool・reporters・coverageの設定変更 | `maxWorkers`・`include`・`setupFiles`だけ | 不要 |

## 3. 既知の不具合と回避策

### setup fileからの`cloudflare:test`のimport

[cloudflare/workers-sdk#16331](https://github.com/cloudflare/workers-sdk/issues/16331)（2026-10-19時点でopen）: Vitest 5では、`setupFiles`が`cloudflare:test`を実行時にimportし、Workerの`main`のmodule graphが大きい（better-authを含む等）と、同じworkerで2ファイル目を実行する前にworkerdが終了する。

- 症状: `Worker exited unexpectedly during started state`。既定の並列数で45ファイル中41ファイル、`--maxWorkers=1`では44ファイルが実行されなかった。単独実行では全ファイル成功。
- 回避: `tests/setup.ts`でpluginの`applyD1Migrations`と同じ処理（同じ`d1_migrations`表・同じ手順）をローカル関数にし、`env`を`cloudflare:workers`から取る。`cloudflare:test`は型だけをimportする。テストファイルからの`applyD1Migrations`のimportは影響を受けないため変更していない。
- 解除条件: 修正版のpluginが出たら、`applyD1Migrations`の呼び出しへ戻す。

### 最初のfetchでのmodule graphの読込

`tests/api.test.ts`はsrcのmoduleを先頭でimportしないため、最初の`exports.default.fetch`がWorkerのmodule graph全体を読み込む。Vitest 5の並列実行ではこれが既定のtest timeout（5秒）を超え、最初のtestが3回連続で失敗した（単独実行では3.8秒で成功）。読込を`beforeAll`（timeout 30秒）へ移した。期待値は変えていない。
