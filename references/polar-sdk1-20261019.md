# Polar SDK 1.0への更新（0.49.0 → 1.0.2）

確認日: 2026-10-19。2026-10-18の依存一括更新（[記録](dependency-update-20261018.md)）で見送ったメジャー更新。影響は任意拡張の決済（標準OFF）の`src/server/billing.ts`だけ。実Polar（sandboxを含む）には接続していない。

## 1. 版・依存・配布元

| 項目 | 内容 | 根拠 |
| --- | --- | --- |
| 採用版 | 1.0.2（2026-10-02公開、dist-tag `latest`）。1.0.3-alphaは対象外 | `npm view @polar-sh/sdk time` / `dist-tags` |
| engines | node `>=22`。Node 26.10.0で満たす | 配布物の`package.json` |
| dependencies / peer | なし（0.49.0はzod・standardwebhooksに依存）。Workersで動かないNode専用依存は増えない | 同上 |
| ライセンス | MIT | 同上 |
| 配布元 | polarsource/polar-jsは2026-09-17にアーカイブ。現在はpolarsource/polarの`sdk/typescript`。0.x→1.0の公式移行ガイドは見つからず、差分は1.0.2の型定義・実装・READMEで確認した | npmの`repository`、GitHub |

`pnpm install --frozen-lockfile`はpeer警告なしで成功した。standardwebhooksは以前から直接依存なので変更なし。

## 2. 破壊的変更と追従

1.0は全面的な書き直しで、Speakeasy生成の0.xとAPIが互換でない。

| 変更点 | 0.49.0 | 1.0.2 | 追従 |
| --- | --- | --- | --- |
| import | `{ Polar } from "@polar-sh/sdk"` | API版ごとのサブパス`{ createPolar } from "@polar-sh/sdk/2026-10"`（他に`2026-04`・`2027-01`）。READMEは`2026-10`を現行版として案内 | `2026-10`を採用。要求に`Polar-Version: 2026-10`が付く |
| client設定 | `server`、`timeoutMs`、`retryConfig` | `environment`（既定production）、`timeout`（秒）。retry設定はない | `environment: serverFor(env)`、`timeout: 8`。未指定をsandboxにする既存の`serverFor`は維持 |
| 引数・応答のキー | camelCase（SDKがwire形式と変換） | wire形式のsnake_caseをそのまま使う | `external_customer_id`・`success_url`・`return_url`・`allow_discount_codes`、応答の`expires_at`・`customer_portal_url` |
| `expires_at`の型 | `Date` | string | providerで`new Date()`へ変換。`BillingProvider`の型と消費側は変更なし |
| 応答の検証 | SDKがZodで検証 | 検証しない（JSONをそのまま返す） | providerで使う項目だけZodで検証（`id`、`url`、`expires_at`はoffset付きISO日時、`customer_portal_url`） |
| エラー型 | `SDKError`等 | `PolarError`、`PolarNetworkError`、`PolarServerError`、`PolarClientError`、`PolarRateLimitError` | 影響なし。billing.tsはSDKのエラー型で分岐せず、送信後の失敗を一律に`uncertain`として扱う |
| webhook | `validateEvent`は旧方式の鍵のみ | `webhooks.validateEvent`は新旧両方式に対応。event型はAPI版に固定 | 変更なし。standardwebhooksで新旧を検証し、消費する項目をZodで検証する既存実装を維持 |

### 再送しないことの確認

1.0.2の`dist/base-*.mjs`（`ClientBase.sendRequest`）は、`AbortSignal.timeout`を付けてグローバル`fetch`を1回呼ぶだけで、再送の処理はない。429は`PolarRateLimitError`を投げるだけ。`checkouts.create`は`buildRequest`→`sendRequest`→`parseResponse`の1往復。既存の`tests/billing-sdk.test.ts`がfetchの呼出し1回・接続先・timeout signal・送信本文を固定しており、1.0でも変更なしで成功した。

## 3. テスト

- 既存: 45ファイル879件はすべて変更なしで成功（fakeのproviderと、グローバルfetchを差し替えたSDK境界テスト）。
- 追加: `tests/billing-sdk.test.ts`に4件。snake_caseの成功応答をcheckout・Portalの戻り値へ対応付けること（Portalの送信本文を含む）と、`url`欠落・`id`欠落・不正な`expires_at`の応答をZodErrorで拒否し、再送しないこと。応答の検証はSDKからこの実装へ移った処理のため追加した。
